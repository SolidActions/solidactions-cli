## Design (implemented)
"CWD-inferred" == `resolveConfig().sources.workspaceId` is a filesystem path that is NOT the global
config path (i.e. a `.solidactions/config.json` found by walking up from CWD). Guard fires on **change**:

| resolution source | last-used | read | write |
|---|---|---|---|
| `-w` / env / global config | any | — | — |
| CWD-inferred | none recorded, or same | — | — |
| CWD-inferred | **differs** | warn (stderr) | confirm; `--yes` or `-w` skips; non-TTY refuses exit 1 |

## Decision ledger

- **Split PRs.** CLI fix = `solidactions-cli` PR; app repo gets a docs-only companion PR, because
  `scripts/issue park` validates `--pr` against `solidactions-app` only. Precedent: #1194, #1293.
- **Guard on CHANGE, not on inference alone.** Confirm fires only when a CWD-inferred workspace differs
  from a recorded last-used one, so the normal same-project workflow stays prompt-free and `-w`/env/
  global-config sources never prompt. *Cost if wrong:* a first write in a new directory prompts once.
- **Unclassified commands default to MUTATING** (fail-safe) so a newly added command can never silently
  skip the guard. *Cost if wrong:* an unclassified read gets a needless prompt (this is what happened
  to the hidden `skill run`).
- **`database pull` is MUTATING** (safe over-inclusion) because `--writable` runs a live SQL REPL;
  classification is command-path-only, so any command writable under ANY flag is classified mutating
  wholesale. Rejected flag-aware classification: machinery for one command.
  *Cost if wrong:* one needless prompt on a plain read-pull after a workspace change.
- **Banner to stderr** (from live smoke): on stdout it corrupts `--json` for script/AI consumers.
  *Cost if wrong:* stdout redirected to a file won't capture the banner — desirable for advisory output.
- **`workspaceOrg` travels with `workspaceId`'s layer**, never picked independently.
  *Cost if wrong:* a wrong org name in the banner — exactly the confusion #1194 fixed.
- **Completeness test excluded hidden commands** (my brief's error) — being corrected to include them.
- **Parked (Task 2 minor):** no symlinked-HOME test; both path inputs derive from the same
  `os.homedir()` call in the real caller, so the divergent-form case is unreachable.
  *Cost if wrong:* an exotic HOME setup silently disables the guard.
- **Test-suite load flakiness** routed to the dev-shop digest rather than filed.
  *Cost if wrong:* a real ordering bug in `database pull` hides behind a "flaky" label.

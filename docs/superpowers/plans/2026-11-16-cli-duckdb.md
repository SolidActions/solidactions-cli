## Review Focus

Task 4 tests all three.
2. **A query on a `duckdb_file` database with nothing published, or while the kind's flag is off** (Task 3): the app answers `no_published_version` or `feature_disabled` with a `{code, message}` error. Expected: the CLI prints the app's own sentence and exits 1, never "The database response was invalid." (today's behaviour on any success shape, `src/commands/database.ts` line 1616) and never a stack. Task 3 tests both codes, plus a success body missing `rows`, which must still fail closed with `upstream_unavailable`.

Expected: `NULL` for null, JSON text for objects (the analytical renderer `formatAnalyticalQueryValue`, line 1763, already does both); the rows arrive as plain JSON, so a bigint beyond 2^53 arrives as a JSON string or number from the server and is printed as received. 4. **`--limit` and truncation** (Task 3): `database query --limit 5` sends `row_limit: 5`; a result with `truncated: true` says so with the row count it printed, never a number the CLI invented. `--limit 0`, `--limit -1` and `--limit abc` stop before any request, as for the analytical kind.
